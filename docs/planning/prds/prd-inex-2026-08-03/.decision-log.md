# Transactions Page Enhancements: Decision Log

Status: active discovery log.

## 2026-08-03 - User review decisions

| ID | Decision | Status | Rationale / consequence |
| --- | --- | --- | --- |
| D-01 | Apply Type and Search filters to the complete selected period, not only the currently loaded ledger page. | Revised by D-20 | A filter yielding five transactions must show all five, even if only one was on the previous first page. Amount filtering is removed from scope. |
| D-02 | Default the selected period to the current month; Clear all returns to that period. | Confirmed | Retains the current period model. |
| D-03 | Make exchange-rate failures obvious in the financial summary. | Confirmed | Use `N/A` and clear copy such as `Rate unavailable for PLN in August 2026`, rather than literal `NaN` or a silently partial total. |
| D-04 | Keep transfer records independently manageable after creation. | Confirmed | A paired-record drill-in or linked edit experience is deferred as a future improvement. |
| D-05 | Do not add multi-select or bulk deletion to this page. | Confirmed | Deletion inside the single-record edit UI is sufficient. |
| D-06 | Do not introduce a broad time-zone policy now. | Confirmed direction | Transactions are manually entered with dates meaningful to the user's locale; exchange-rate mapping is the only identified future motivation. Backend date validation is still being evaluated separately from time-zone policy. |
| D-07 | Retain advanced filters after the drawer closes/reopens and restore them from the URL query when supplied. | Confirmed | Supports revisiting and sharing the filtered view. |
| D-08 | Keep the first-use empty state focused on adding a transaction. | Confirmed direction | Accounts and categories are seeded, so prerequisite-empty guidance is not currently needed. |
| D-09 | Reorder desktop ledger columns to Description, Account, Date, Amount; retain Amount-first mobile rows. | Confirmed | Desktop Amount is the final, right-aligned visual boundary. On mobile, Amount-first provides the fastest scan of financial impact after the table header disappears. |
| D-10 | Place Category before Amount in the new income/expense transaction form. | Confirmed | Intended flow: choose paying/receiving account, choose purpose/category, enter amount, then date/comment. |
| D-11 | Close the edit drawer after a successful save. | Confirmed | Save completion should return the user to the updated ledger. |
| D-12 | Add an on-demand active-account summary to Transactions. | Confirmed | Show every active account with its native-currency balance. Use a desktop companion panel, mobile drawer, and selected-account inline balance. |
| D-13 | Keep the current page typography, colours, sizing, and page-area differentiation as reusable design guidance. | Confirmed direction | The final UX artifact must describe transferable visual tokens and component patterns. |
| D-14 | Replace low-value Net flow secondary copy with a comparison to the previous period. | Confirmed | A whole month compares with the immediately preceding whole month; a custom range compares with the immediately preceding range of equal length. |
| D-17 | Add server-side presence validation for transaction dates, without introducing a time-zone model or future-date policy. | Confirmed | The product uses user-entered local calendar dates; the server must reject an omitted/default date while no time-zone conversion is in scope. |
| D-15 | Provide an immediate Clear filters action wherever active filters are indicated. | Confirmed direction | The active-filter marker must also offer a quick reset, rather than only signalling state. |
| D-16 | Show income-only and expense-only transaction counts in the Income and Expenses KPI card secondary rows. | Confirmed | The current repeated total transaction count is not useful in these two cards. |
| D-18 | Show both absolute and percentage Net flow change when the previous comparable period has non-zero net flow; show only absolute change when it is zero. | Confirmed | Avoids an undefined or misleading percentage while preserving useful comparison context. |
| D-19 | Handle prior-period Net flow comparison evidence explicitly. | Confirmed | Show absolute change only with `No activity in [period]` when the preceding comparable period has no transactions. If either period has incomplete conversion data, show `N/A` and the affected currency/period Rate Warning. |
| D-20 | Remove Amount filtering from Transactions. | Confirmed | Account and Category are more useful discovery criteria. Removing Amount avoids an inconsistent page-local filter and unnecessary Base Currency/rate complexity. |
